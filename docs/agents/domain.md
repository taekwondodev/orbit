# Domain documentation

This repository has one bounded context. Use [GLOSSARY.md](../../GLOSSARY.md) for domain terms, including issue titles, specifications, tests and commit messages.

Before changing resource ownership, provisioning, authorization, lifetime, networking or SSH readiness, read the relevant decisions in [docs/adr](../adr/). Identify any conflict with an existing decision before proposing its replacement.

Keep definitions in the glossary, decision rationale in ADRs, current behavior in [architecture](../architecture.md) and [design contracts](../design/), and task-specific evidence in the issue or task record. Link to the owner instead of copying its rules. A missing domain term is a gap to resolve, not a reason to introduce a synonym.
